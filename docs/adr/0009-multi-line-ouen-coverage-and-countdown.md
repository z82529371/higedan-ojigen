# 應援區間跨句多行涵蓋與應援前倒數機制

## 背景與問題
歌迷在演唱會中進行應援（如拍手、合唱、手勢）時，經常會持續數句歌詞的時間。若資料格式要求依照每句歌詞切割 JSON 應援點，會增加維護成本；且若靜態頁面上僅有第一句顯示標記，後續句子滾動時歌迷容易失去應援提示。此外，歌迷需要提前預知應援點開始時間，以精準接唱或入場。

## 決策
1. **應援區間跨句多行涵蓋（Multi-line Ouen Coverage, 方案 A）**：當一個應援點的時間區間（`start` ~ `end`）跨越多行歌詞時，凡與該區間有時間重疊的所有歌詞行，皆會自動顯示對應的應援標記。完整歌詞模式下，歌詞文字主體保持乾淨原色，僅**左側邊條（Border Line）**與類別標籤（如 `(合唱)`）常駐渲染為對應應援色（合唱 `#d97706` 暖金琥珀、手勢 `#ea580c` 活力暖橘、拍手 `#db2777` 亮紫玫粉）。
2. **應援前 3 秒單行置頂倒數（Line-head 3-2-1 Countdown）**：在播放時間距離下一個應援點開始剩餘 3.0 秒內時，僅在該應援區間涵蓋的**第一行歌詞上方**顯示獨立置頂倒數標記（`⏳3` ➔ `⏳2` ➔ `⏳1`），避免多行重複跳出倒數干擾視覺。
3. **顯式指定 text 的局部口號染色與手勢垂直對齊**：當應援動作 `action` 明確指定 `text`（例如 `text: "(Yeah)"`）且歌詞中含有對應括號時，全句歌詞不染全句背景/字體色，僅將括號內文字 `(Yeah)` 常駐染為應援色；同時間若帶有手勢 Emoji（如 `🙌`），手勢會精準垂直置頂對齊於 `(Yeah)` 括號文字正上方，頂部列自動過濾不重複顯示。
4. **極簡化類別標頭與字體系統**：完整歌詞模式標籤簡化為 `(合唱)`、`(手勢)` 等格式；全站字體採用 **Plus Jakarta Sans + Noto Sans JP/TC**，播放鍵與進度條等輔助 UI 色採 `#b8a024` 經典高雅金。

## 後果
- **正面**：JSON 資料維護極簡化，單一廣域時間區間即可完整涵蓋連續應援；局部口號（如 `(Yeah)`）能精準局部染色且手勢直覺置頂對齊，畫面極致乾淨。
- **負面**：當應援區間較長時，多行歌詞會同時呈現相同的 Emoji 標記。
