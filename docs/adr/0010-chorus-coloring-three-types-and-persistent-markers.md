# 合唱染色三分類與標記常駐化（取代括號染色）

## 背景與問題
舊方案（ADR 0009 決策 3）將合唱的局部口號染色綁定於「歌詞含括號」的既有格式：當 `action.text` 是括號片段（如 `(Yeah)`）且歌詞含括號時，僅染括號文字並把同時的手勢 Emoji 垂直置頂對齊於括號上方，頂部列過濾不重複顯示。此設計在真實歌曲資料中造成幾項問題：
- 染色依賴「歌詞恰好含括號」的巧合，無法涵蓋「歌詞本身沒有括號、口號要另外寫」的段落。
- 手勢置頂對齊是視覺特例，與「手勢一律以 emoji 原生呈現」的簡潔原則衝突。
- 括號內容（`text`）被同時當作「染色片段」與「補充文字」兩種用途，語意混雜。

## 決策
1. **合唱動作三分類（Three-way Chorus Coloring）**：每個合唱動作依 `text` 有無與能否在歌詞中命中，分成三種型態：
   - **合唱一整句**：無 `text`，該應援點涵蓋的歌詞行整行染色。
   - **唱一部分**：有 `text` 且在涵蓋的歌詞行內找得到對應片段，僅該片段染色（所有相符片段皆染）。
   - **不是唱這句歌詞**：有 `text` 但在涵蓋的歌詞行內找不到，不染歌詞，僅顯示獨立標記（可附 `romaji`）。
   `text` 有值時只在該應援點涵蓋的歌詞行內找對應片段。
2. **移除括號染色與手勢垂直置頂**：不再以括號格式觸發局部染色，手勢一律在標記列顯示 emoji、不做垂直置頂對齊；歌詞含括號時標記照常顯示（不做過濾）。`ADR 0009 決策 3 已過時`。
3. **兩種模式皆為常駐染色**：完整歌詞與卡拉OK模式的涵蓋歌詞行皆依三分類恆常染色，左條與類別標示 `(合唱)` 同步常駐，不隨播放時間變化；標記常駐顯示，進入應援點區間時亮起。
4. **優先序**：一行同時被多個合唱應援點涵蓋時，`合唱一整句` 優先於 `唱一部分`。
5. **預設模式**：播放頁模式切換預設為「完整歌詞模式」（原預設卡拉OK）。

## 後果
- **正面**：合唱染色與歌詞格式解耦，三種型態語意清晰；手勢回歸統一標記呈現；兩種模式行為一致。
- **負面**：`唱一部分` 需要在資料製作時確認 `text` 能命中歌詞字串（含半形/全形差異），否則退化成「不是唱這句歌詞」的獨立標記。
